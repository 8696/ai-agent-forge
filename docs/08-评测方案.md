# 08 · 评测方案

> **状态**：D1 已落地（2026-10-24）。本文档是「怎么评」的规格；
> 落地细节（接口 / 表 / 页面）见 [12-d-需求-运维稳定.md §D1](./12-d-需求-运维稳定.md)。

## 8.1 评测集

- 初始评测集 200 条，覆盖：退款咨询、改地址、年假政策、订单查询、闲聊
- 评测集文件格式：JSONL，每条 `{question, reference_answer, scenario, difficulty}`
- 评测集版本管理：每次更新打版本，可回滚

> **落地偏差**：
> - 单次跑批的题数上限是 **50 条**（`EVALUATION_MAX_ITEMS`），不是 200 ——
>   一条题 = 2 次 LLM 调用（生成 + 裁判），200 条 = 400 次调用，成本闸门必须挡着。
>   200 条的评测集可以建、可以分批跑
> - **版本是字符串**（`v1` / `v2`），不是整数递增；不强制「同名同版本唯一」
> - 「可回滚」🚫 **不做**（用户 2026-10-26 拍板：版本是字符串标签，
>   「新增版本 + 前后两次跑批对比」已覆盖实际用法，真要回滚多建一个版本即可）。
>   见 [12-e 裁定表](./12-e-需求-业务接入与平台运营.md) #14

## 8.2 评测指标

| 维度 | 评分方式 | 说明 |
|------|----------|------|
| 准确性 | 大模型当裁判 | 与参考答案的一致性 |
| 完整性 | 大模型 | 是否覆盖所有要点 |
| 风格 | 大模型 | 与品牌风格匹配 |
| 安全 | 规则 + 大模型 | 无敏感内容 |
| 延迟 | 程序测 | p95 ≤ 3 秒 |
| 成本 | 程序测 | 单条 ≤ $0.05 |

> **落地偏差**：
> - 四维分数是 **0~5 分**（不是 0~1 比例），跟裁判的五档口径一致：
>   5 = 完全正确 / 4 = 基本正确 / 3 = 方向对但有缺失 / 2 = 只答对一部分 / 1 = 沾边 / 0 = 完全错
> - **延迟 / 成本是「程序测」的**（不占裁判的四维）：
>   每条明细存 `latency_ms` 和 `cost`，跑批详情页给出 **p95 延迟** / **单条最高成本** / **平均成本**
> - **安全维度目前只用大模型裁判**（`docs/10-安全方案.md` 的规则层是给「用户输入」用的，
>   评测里对的是模型**输出**，规则词表那一层没有单独接）
> - 「p95 ≤ 3 秒 / 单条 ≤ $0.05」是**目标**，当前只展示数字、不做拦截

## 8.3 评测流程

- 每次 prompt 改动自动跑小规模相关测试 ✅ **2026-10-26 已做**（迁移 `033` + `src/services/prompt-regression.ts`）
- 手动触发跑批 ✅
- 评测结果写进数据库，画趋势图 ✅
- 分数下跌 ≥ 10% 触发告警 ✅

> **落地说明**：
> - **「每天定时自动跑全量」已移出需求**（2026-10-25）—— 不在本项目范围内，
>   评测只支持**手动触发**（后台点「跑评测」）
> - **prompt 改动自动回归已做**（2026-10-26）：挂在 C3 的 publish / rollback 动作上，
>   发布后**异步**跑前 10 题（`run_trigger='prompt_regression'`），**永不阻塞发布**；
>   没评测集 / 评测关着 / 起跑失败 → 一律跳过
> - **跑批是后台异步的**：接口返 202 + run id，实际工作在后台跑，页面 5 秒轮询进度。
>   50 题 = 100 次 LLM 调用，同步跑 HTTP 必超时
> - **「分数下跌 ≥ 10%」的比较基准是「同一个评测集的上一次跑批」**
>   （不是「周环比」—— `docs/09-观测方案.md` §9.4 写的是周环比）：
>   同一个评测集的前后两次才有可比性，换了评测集分数没有可比性。
>   跌 ≥ 10% 写一条 `EVALUATION_SCORE_DROPPED` 审计告警 → 后台顶栏告警条显示
> - **单条题失败不中断整批**：跳过后整批照常出分，分母是**成功打分的条数**
