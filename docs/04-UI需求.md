# 04 · UI 需求（完整版 · 可交付的产品 UI 规范）

> 这份文档是**前端工程师照着就能做**的 UI 规范。读完后能完整搭建出本系统的所有页面。
> 框架：**Ant Design 5**（React 18 + Vite）；不支持 Next.js、不用 Tailwind、不用 shadcn/ui。
> 所有可见文案用**中文**（zh_CN locale）。

## 0. 设计总则

### 0.1 技术选型

| 项 | 选型 |
|----|------|
| 组件库 | **Ant Design 5** |
| 样式 | AntD ConfigProvider + token 定制（不引 Tailwind） |
| 路由 | React Router DOM 6 |
| 状态管理 | Zustand（按业务拆 store） |
| HTTP | Axios + 拦截器 |
| 图表 | ECharts（`echarts-for-react`） |
| Markdown | react-markdown + remark-gfm + highlight.js |
| 实时通信 | SSE（`fetch` + ReadableStream） |
| 时间 | Day.js（AntD 配套） |
| 图标 | `@ant-design/icons` |
| 表单 | AntD Form + Zod 校验 |
| 错误兜底 | react-error-boundary |

### 0.2 主题与色彩

| Token | 值 | 用途 |
|-------|----|----|
| `colorPrimary` | `#1677ff` | 主题蓝（AntD 默认） |
| `colorSuccess` | `#52c41a` | 成功 / 已索引 |
| `colorWarning` | `#faad14` | 警告 / 索引中 |
| `colorError` | `#ff4d4ef` | 错误 / 失败 |
| `borderRadius` | `6` | 通用圆角 |
| `fontSize` | `14` | 基础字号 |

- **支持深色模式**（AntD `theme.darkAlgorithm`），右上角切换
- 浅色为默认

> **整页不引用任何图片资源**。UI 装饰元素（icon / logo / avatar / 占位）一律用 **AntD 图标**（`@ant-design/icons`）替代。

| 场景 | 不要 | 改用 |
|------|------|------|
| 公司 Logo | `image: 'logo.png'` | `<Avatar shape="circle" style={{ background: '#1677ff' }}><RobotOutlined /></Avatar>` |
| 用户头像 | `image: avatar.png` | `<Avatar icon={<UserOutlined />} />`（无头像时） |
| 文件类型图标 | `image: file-icon.png` | `<FilePdfOutlined />` / `<FileWordOutlined />` / `<FileTextOutlined />`（按扩展名选） |
| 占位插画 | `image: empty.png` | AntD `<Empty />`（自带 SVG） |
| 状态指示 | `image: success.png` | AntD `<Badge status="success" />` / `<CheckCircleOutlined />` |
| 操作按钮图标 | `image: button.png` | AntD `icon` prop（如 `<Button icon={<DeleteOutlined />}>删除</Button>`） |

**例外（这些是真内容，不是 UI 装饰）**：
- 用户上传的图片（聊天里发给 AI 看的）
- AI 生成的图片（图像生成功能输出）
- 用户上传的文档预览（PDF 第一页缩略图）

> 例外里的图片用 `<img>` 标签或 AntD `<Image>` 组件展示；其余一律 AntD 图标。

## 3. 登录页面（3 个）

> **所有登录页都遵循**：全屏居中卡片 + 居中 logo + 标题 + 表单 + 按钮。
> 三个登录页用不同路由 + 相似布局 + 不同文案。

### 3.1 系统级登录 `/system/login`

| 字段 | 必填 | 校验 |
|------|------|------|
| 邮箱 | ✓ | 邮箱格式 |
| 密码 | ✓ | ≥ 8 字符 |
| 验证码（可选） | — | — |

- 提交：`POST /api/v1/system/login`
- 成功 → 跳 `/system`
- 失败：`401 邮箱或密码错误`（不泄露用户是否存在）
- 「**没有 SaaS 平台方账号？联系系统部署方**」提示文案

### 3.2 租户后台登录 `/admin/login`

| 字段 | 必填 | 校验 |
|------|------|------|
| **租户号** | ✓ | `[a-z0-9-]{3,32}` |
| 邮箱 | ✓ | 邮箱格式 |
| 密码 | ✓ | ≥ 1 字符 |
| 「记住我」 | — | localStorage 存 JWT 7 天 |

- 提交：`POST /api/v1/auth/login` 带 `login_type: 'admin'`
- 成功 → 跳 `/admin/dashboard`（若 `must_change_password=true` 强制跳改密页）
- 失败：`401 邮箱或密码错误`
- 「**租户号由你的 SaaS 服务方提供**」副文案
- 「**租户号格式**：3-32 位小写字母 / 数字 / 短横线（例：acme-corp）」

### 3.3 前台用户登录 `/account/login`

| 字段 | 必填 | 校验 |
|------|------|------|
| **租户号** | ✓ | 同上 |
| 邮箱 | ✓ | 邮箱格式 |
| 密码 | ✓ | ≥ 1 字符 |

- 提交：`POST /api/v1/auth/login` 带 `login_type: 'customer'`
- 成功 → 跳 `/account/chat`（或默认页）
- 「**没有账号？联系你的租户管理员**」副文案

### 3.4 公共部分

- 卡片宽度：400px
- 顶部：公司 Logo（占位用 AntD `RobotOutlined` 蓝色背景圆 + 文字「AI」）
- 标题：「登录到 AI 助手」
- 副标题：根据登录类型变化文案
- 输入框：标准 AntD `<Input />` + `<Input.Password />`
- 登录按钮：`<Button type="primary" block>登录</Button>`
- 「忘记密码」（v1 不实现，UI 留位 + 灰色禁用 + 提示「请联系管理员」）

### 4.5 图像理解 + 图像生成

#### 4.5.1 图像理解（v1 实现）

- 用户点 📎 选「图片」→ 上传 → **图片缩略图**插入到输入框（**缩略图例外**：用户上传的内容是真内容，不是 UI 装饰）
- 发送后：用户气泡显示图片缩略图 + 文字
- AI 收到图片后能识别内容（依赖底层大模型支持视觉，如 Claude Sonnet 支持图片）
- 上传前显示：「📎 待发送：image.png [× 删除]」（缩略图 + AntD `<CloseOutlined />` 删除按钮）

#### 4.5.2 图像生成（v1 占位 / Phase 2 实现）

- 输入框上方有「🎨 图像生成」开关（v1 UI 留位，灰显 + tooltip「即将推出」）
- 开启后：输入框变成 prompt 框；点发送 → 等待 → 弹出图片
- 后端接 DALL-E / Stable Diffusion / 智谱 CogView

> **图像生成结果例外**：用 AntD `<Image.PreviewGroup>` 展示生成的图，支持点击放大。生成进度用 AntD `<Progress />` + `<Spin />`，不用自定义图片。

### 4.10 流式聊天实现（关键 · 用 Vercel AI SDK）

> 「流式」= AI 边生成边返回，UI 边收边显示，**不等全部生成完**。这是聊天产品的核心体验。

#### 4.10.1 用了什么库

| 端 | 用什么 | 作用 |
|----|------|------|
| **后端** | **`ai`**（Vercel AI SDK 核心）+ **`@ai-sdk/anthropic`**（Anthropic provider 适配器） | `streamText()` 一句拿流式 token + 工具调用 |
| **后端 → 前端** | **SSE**（Server-Sent Events） | Vercel AI SDK 自动转 SSE 格式 |
| **前端** | **`@ai-sdk/react`** 的 **`useChat()` hook** | 1 行接 SSE、自动状态管理、自动重连 |

> **关键决策**：用 Vercel AI SDK 是因为它**比直接调 Anthropic SDK 更简单**（5 行 vs 30 行），且跟前端 `useChat()` 无缝对接。

#### 4.10.2 数据流

```
[前端] 用户点发送
   │
   │ const { append } = useChat() → fetch('/api/chat')
   ▼
[后端 Koa]  ctx.body = streamText({...}).toDataStreamResponse()
   │
   │ Vercel AI SDK 自动调 Anthropic SDK
   ▼
[@ai-sdk/anthropic]  streamText 边生成边返回
   │
   │ Vercel AI SDK 自动转 SSE
   ▼
[SSE 响应]  "0:" + JSON({type:'text', delta}) + "\n" + ...
   │
   │ useChat() 解析
   ▼
[前端 React state]  messages 数组更新
   │
   ▼
[用户屏幕]  看到 AI 逐字出现
```

#### 4.10.3 后端关键代码（**5 行**）

```typescript
// src/gateway/chat-stream-routes.ts
import { streamText } from 'ai';
import { anthropic } from '@ai-sdk/anthropic';
import { Readable } from 'node:stream';

router.post('/api/v1/chat/stream', async (ctx) => {
  const { messages } = chatInputSchema.parse(ctx.request.body);

  const result = streamText({
    model: anthropic('claude-sonnet-4-5'),
    system: systemPrompt,
    messages: convertToModelMessages(messages)  // 转成 CoreMessage[]
  });

  // Vercel AI SDK 返回标准 Response 对象
  const response = result.toDataStreamResponse();
  ctx.status = response.status;
  response.headers.forEach((v, k) => ctx.set(k, v));
  ctx.body = response.body ? Readable.fromWeb(response.body) : null;
});
```

**对比之前**：30 行（手写 Anthropic SDK 调用 + SSE 响应头 + event 循环）。**现在 5 行**。

#### 4.10.5 UI 上的流式表现

| 状态 | UI |
|------|-----|
| 用户点发送 | 立即看到「✍ 思考中...」+ AntD `<Spin />` |
| 流式回包中 | AI 气泡从「**空**」到「**逐字出现**`（由 useChat 自动维护 messages 数组触发 React 重渲染） |
| 流式结束 | 完整气泡出现 + 「👍 👎 复制」操作行 |

#### 4.10.6 用了 Vercel AI SDK 还省了哪些事

| 原本要做的 | Vercel AI SDK 自带 |
|-----------|------------------|
| 写 SSE 响应头（`Content-Type: text/event-stream` 等） | `toDataStreamResponse()` 自动加 |
| 手写 SSE 事件格式（`event: text\ndata: ...\n\n`） | 自动 |
| 解析 SSE 流（split by `\n\n` + 解析 `event:` `data:`） | `useChat()` 自动 |

| 重连机制 | `useChat()` 自动重连 |
| 工具调用协议（function calling → 工具执行 → 结果回灌） | `tool({...})` helper + `streamText` 自动循环 |
| Structured Output（Zod 校验 + 解析） | `generateObject()` + `output: 'structured'` |
| 流式 token 计数 + 成本统计 | `result.usage`（含 `promptTokens` / `completionTokens`） |

- 成本现在按月 → 未来加「按部门 / 按项目」拆解

### 10.4 插件机制（v2 考虑）

- 工具 = 插件（已通过 MCP 实现雏形）
- 提示词 = 模板库（v1 是文件 + 版本；v2 考虑模板引擎）
- 评测场景 = 插件（不同行业有不同评测集）
