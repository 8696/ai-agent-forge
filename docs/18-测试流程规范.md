# 18 · 测试流程规范（**Agent 必读 · 硬约束**）

> **本份是测试相关的「流程 + 规则」唯一文档**。所有 Agent 写 / 改 / 加接口和页面时必须按本份执行。
> 技术细节见 `16-d-需求-运维稳定.md §D6 测试基建契约`（目录结构、命令、凭据）。
> 项目级硬约束见 `AGENTS.md §6.4 自动化测试硬约束`（违规即测试跑不起来）。

---

## 18.1 一句话目标

**每一次写 / 改接口或页面，必须同步写 / 改对应的测试文件。** 1 个接口文件 ↔ 1 个测试文件，**禁止漏写、禁止跳过、禁止等"以后补"**。

---

## 18.2 测试金字塔（三层目录 + 三类命令）

```
tests/
├── unit/                  # vitest 单测：测纯函数 / 工具 / 模型方法
├── integration/           # vitest 集成测试：测 API 端点（1-to-1 路由文件）
└── e2e/                   # Playwright 浏览器（Step 13 UI 验收时启用）
```

| 层级 | 命令 | 何时跑 | 谁触发 |
|---|---|---|---|
| **fixtures** | `yarn test:fixtures` | 改完 fixtures 后 | Agent（手动） |
| **unit** | `yarn test:unit` | 改 `src/lib/` / `src/models/` 后 | Agent（手动） + CI |
| **integration** | `yarn test:integration` | 改路由 / 写新接口后 | Agent（手动） + CI |
| **e2e** | `yarn test:e2e` | 改前端页面后（未来） | Agent（手动） + CI |

## 18.3 核心规则：**接口 1-to-1 测试**

### 18.3.1 后端接口（路由文件）

**规则**：每个 `src/gateway/<子系统>/<X>-routes.ts` 文件 ↔ 一个 `tests/integration/<X>.test.ts` 文件，**文件名去 `-routes` 后缀**。

| `admin/knowledge-routes.ts` | `admin-knowledge.test.ts` |
| `admin/sessions-routes.ts` | `admin-sessions.test.ts` |
| `customer/auth-routes.ts` | `customer-auth.test.ts` |
| `customer/chat-routes.ts` | `customer-chat.test.ts` |
| `customer/sessions-routes.ts` | `customer-sessions.test.ts` |
| `chat-routes.ts` | `chat.test.ts` |

### 18.3.2 前端页面（未来 Step 13+）

**规则**：每个 `web/pages/<子系统>/<Page>.tsx` ↔ 一个 `tests/e2e/<page>.spec.ts`（Playwright）。**占位先用 `tests/e2e/README.md` 标记，待 Playwright 落地再补**。

### 18.3.3 纯函数 / 工具

**规则**：每个有逻辑的 `src/lib/<X>.ts` ↔ 一个 `tests/unit/<X>.test.ts`。**模型 / 中间件 / 路由 barrel** 可选（看复杂度，逻辑多的写）。

## 18.4 工作流程（每次写 / 改接口时）

### 18.4.1 新增接口 / 页面

```
1. 改 16-需求技术对照表（拆 16-a..16-e 对应子文件）：加新需求
2. 改 docs/05（数据模型）：加新表 / 字段
3. 改 docs/06-API接口.md：加新端点
4. 改 src/gateway/<子系统>/<X>-routes.ts：实现端点
5. 改 tests/integration/<X>.test.ts：加测试用例        ← 同步
   └─ 缺文件？先建空骨架（从现有 route test 复制 describe 头）
6. 跑 yarn typecheck → 0 错
7. 跑 yarn test:integration → 新用例通过
8. 改 docs/15-开发进度计划.md：⬜ → ✅
9. git commit
```

### 18.4.2 修改已有接口

```
1. 改 src/gateway/<子系统>/<X>-routes.ts：改端点
2. 改 tests/integration/<X>.test.ts：同步更新对应 it()    ← 同步
   └─ 接口行为改了但测试还通过 → 测试有问题（说明测试没覆盖到行为）
3. 跑 yarn typecheck + yarn test:integration
4. 改 docs/06-API接口.md：端点行为变化要同步
5. git commit
```

### 18.4.3 删除接口

```
1. 删 src/gateway/<子系统>/<X>-routes.ts：删端点
2. 删 tests/integration/<X>.test.ts：删对应 it()           ← 同步
3. 跑 yarn test:integration → 不应该有 stale 用例
4. 改 docs/06-API接口.md：端点表删除
5. git commit
```

## 18.4.1 跑哪些测试 · 决策表（**改完必查**）

> **核心原则**：**最小集**——只跑能验证本次改动的测试；**改共享层**才跑全套。
> 跑错 = 浪费时间（最小集漏跑）或被海量 fail 淹没（不该跑全套时跑了）。

### A · 改了 `tests/**/*.test.ts` 里的用例

| 改动范围 | 跑什么 | 命令 |
|---|---|---|
| 单个 `it()` 加 / 改 | 只跑该文件 | `yarn test:unit` 会被 `vitest run` 自动定位到对应 `.test.ts`；或 `yarn vitest run tests/<dir>/<file>.test.ts` |
| 改了 `beforeAll` / `afterAll` 里的 setup | 同上 | 同上 |
| 改了 mock / fixture | 同上 | 同上 |
| 改了 `tests/setup.ts`（globalSetup） | **全套**（setup 影响所有 .test.ts） | `yarn test:integration` 或 `yarn test:unit` 视改动影响面 |
| 新增 / 删除了 .test.ts 文件 | 全套（确认 0 fail） | `yarn test:integration` 或 `yarn test:unit` |

### B · 改了 `src/` 后端代码

| 改动文件 | 跑什么 | 命令 |
|---|---|---|
| `src/lib/<X>.ts`（纯函数） | 该 lib 的 unit 测试 | `yarn test:unit` 自动定位；或 `yarn vitest run tests/unit/<x>.test.ts` |
| `src/lib/<X>.ts` 被多个文件 import | unit + 至少 1 个 integration smoke | `yarn test:unit && yarn test:integration -- tests/integration/smoke-lib.test.ts` |
| `src/gateway/<子系统>/<X>-routes.ts`（路由） | 该路由对应的 .test.ts | `yarn vitest run tests/integration/<x>.test.ts` |
| `src/gateway/error-handler.ts` / `src/gateway/jwt-base.ts` / `src/gateway/api-key-auth.ts`（**middleware / 全局**） | **全套 integration** | `yarn test:integration` |
| `src/models/<X>.ts`（模型） | 该模型的 unit + 引用它的 integration | 先 `yarn test:unit`，再跑相关 integration |
| `src/config.ts` / `src/db.ts`（基础设施） | **全套** | `yarn test`（unit + integration 全跑） |
| 新增 `src/gateway/<子系统>/<X>-routes.ts` | 必须**先建** `tests/integration/<x>.test.ts`，再跑该新文件 + smoke 确认未破坏现有 | `yarn vitest run tests/integration/<x>.test.ts tests/integration/smoke-lib.test.ts` |
| `src/migrations/<N>.ts`（迁移） | 必跑 `yarn migrate` 跟真实 DB；再跑全套确认没破坏 | `yarn migrate && yarn test` |

### C · 改了 `web/` 前端代码

| 改动文件 | 跑什么 | 命令 |
|---|---|---|
| 改了某个 `.tsx`（不动 API） | 只跑 `yarn typecheck` | `yarn typecheck`（web 端 vitest 暂未启用） |
| 改了调 API 的 `web/lib/<X>.ts`（如 `customerApi.ts`） | typecheck + 后端对应端点的 integration（确认契约没变） | `yarn typecheck && yarn vitest run tests/integration/<对应路由>.test.ts` |
| 改了 vite.config.ts / tsconfig.web.json | typecheck | `yarn typecheck` |
| 新增 / 删除前端页面 | typecheck + 端到端 smoke（如果后端有相关 endpoint 测试） | `yarn typecheck && yarn vitest run tests/integration/smoke-lib.test.ts` |

### D · 改了测试基建

| 改动文件 | 跑什么 | 命令 |
|---|---|---|
| `tests/fixtures/fixtures.json` | 重跑 seed + e2e:login + smoke（确认凭据 + JWT 没变） | `yarn test:fixtures && yarn test:integration -- tests/integration/smoke-lib.test.ts` |
| `tests/fixtures/seed.ts` | 同上 | 同上 |
| `tests/helpers/{auth,http,fixtures}.ts` | **全套**（helpers 被所有测试 import） | `yarn test` |
| `tests/helpers/login-all.mjs` | `yarn e2e:login` 确认能拿到 7 个 token | `yarn e2e:login` |
| `vitest.config.ts` | **全套**（白名单 / globalSetup / pool 改了都影响） | `yarn test` |

### E · 改了文档（`docs/`）

**不跑测试**。但**改了 docs/16 / 06 / 05 / 13 / 14** → 必跑"文档 ↔ 代码对照"验证（§18.8）。

---

### 速记（**4 句话**）

1. **改 1 个 it() / 1 个 .test.ts** → 跑那 1 个文件
2. **改 1 个路由 / 1 个 lib** → 跑那 1 个对应 .test.ts
3. **改 middleware / 基建 / 基础设施 / 新增 .test.ts** → 跑**全套**
4. **改前端 .tsx 不动 API** → 只跑 `yarn typecheck`

### 反例（禁止）

- ❌ 改了 `admin-auth.test.ts` 一个 it() 就跑 `yarn test` 全套
- ❌ 改了 `src/lib/jwt.ts` 就跑全套（应只跑 `tests/unit/jwt.test.ts`）
- ❌ 改了前端 1 个 `.tsx` 不动 API 也跑全套 integration
- ❌ 反过来：改了 `tests/setup.ts`（globalSetup）只跑那 1 个文件 → 其他文件的 globalSetup 行为没验

## 18.5 测试用例最低覆盖（**每接口必跑**）

每个端点至少覆盖：

| 场景 | 必测 | 备注 |
|---|---|---|
| **Happy path** | ✅ | 正常输入 → 期望状态码 + 关键字段 |
| **未鉴权** | ✅ | 不带 token → 401 |
| **跨租户防御**（仅 tenant-scoped 端点） | ✅ | 用另一个租户的 token → 403/404 |
| **参数校验失败** | ⭕ 至少 1 个 | 缺字段 / 错类型 → 400 |

**额外规则**：

- 鉴权 / 错误响应统一走 `validateStatus: () => true`，避免 axios 抛错打断测试
- 用例命名 `<端点> · <场景>`（如 `POST /login · 200 + token`、`POST /login · 401 密码错`）
- 不要写"测这个函数返回 X"这种白盒测试，要写"调这个端点，HTTP 响应里有什么"

## 18.6 测试文件模板（**新文件必须照这个抄**）

```typescript
/**
 * tests/integration/<X>.test.ts
 *
 * 对应 src/gateway/<子系统>/<X>-routes.ts
 * 详见 docs/18-测试流程规范.md §18.3
 */
import { describe, it, expect, beforeAll } from 'vitest';
import { allHttpFromTokensFile, type AllHttp } from '../helpers';

describe('<X>-routes', () => {
  let http: AllHttp;

  beforeAll(async () => {
    http = await allHttpFromTokensFile();
  });

  describe('POST /login（举例）', () => {
    it('POST /login · 200 + token', async () => {
      const r = await http.<子系统>.<子系统>.post('/login', { ... });
      expect(r.status).toBe(200);
      expect((r.data as { token: string }).token).toMatch(/^eyJ/);
    });

    it('POST /login · 401 密码错', async () => {
      const r = await http.<子系统>.<子系统>.post(
        '/login',
        { ... },
        { validateStatus: () => true },
      );
      expect(r.status).toBe(401);
    });
  });
});
```

**禁止**：

- ❌ 手写 `function check(label: string, ok: boolean): void { ... }` 自造断言
- ❌ 用 `console.log` + `process.exit(1)` 充当测试框架（老 `test-stepN.ts` 是兼容层）
- ❌ 在测试里硬编码邮箱 / 密码 / API key
- ❌ 用 `Date.now()` 后缀造测试租户
- ❌ 写完新接口不写测试 → 视为未完成

## 18.7 fixtures 与测试隔离

- 跑测试前 `tests/setup.ts` 自动跑 `yarn seed` + `yarn e2e:login`
- 测试租户固定 `acme` / `globex`，跨用例共享（不重建）
- 端点创建数据用 `Date.now()` 后缀避免主键冲突（**租户 / 用户 / API key 本身不后缀**）
- 跨租户防御用例：用 `globex` token 访问 `acme` 资源，期望 403/404

## 18.9 检查清单（每次 PR 前自检）

- [ ] 改 / 加的每个接口文件，对应 `tests/integration/<X>.test.ts` 都同步更新
