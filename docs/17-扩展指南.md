> 这份文档是「**怎么往实时文档里加新东西**」的指南。

## 17.2 怎么新增一条需求

**唯一位置**：`16-需求技术对照表.md`（其他文件不再写需求清单）

步骤：

1. **打开 `16-需求技术对照表.md`**
2. **找到对应的 A / B / C / D / E 章节**
3. **按下面的模板加一条**
4. **在 16 末尾的「按需求 ↔ 技术」索引里同步加**
5. **在 `15-开发进度计划.md` 里找到合适步骤，在「涉及需求」里引用这条编号**（如「涉及需求：B7」）
6. **不需要在 `01-需求与场景.md` 里加**，因为 01 已经指向 16

### 需求命名约定

| 前缀 | 类别 |
|------|------|
| `A*` | 多租户基础 |
| `B*` | AI 对话能力 |
| `C*` | 管理员可配置 |
| `D*` | 运维稳定 |
| `E*` | 业务接入 |

下一个编号看当前已有的最大编号往下排。

### 新增需求模板

```markdown
#### {前缀}{N} · {需求名}

**需求**：{一句话}

**对应 Step**：Step N / Step M

**使用技术**：
- {技术 1}
- {技术 2}

**实现位置**：
- {文件 / 路由 / 函数 1}
- {文件 / 路由 / 函数 2}

**关键代码**：
{关键模式代码}

**验收**：
- {怎么测 1}
- {怎么测 2}
```

### 示例：加一条「B7 · 流式打字机效果」

```markdown
#### B7 · 流式打字机效果

**需求**：AI 回答逐字显示（打字机效果），不等全部生成完再返回。

**对应 Step**：Step 5

**使用技术**：
- Anthropic SDK `messages.stream`（流式 API）
- SSE（Server-Sent Events）
- 前端 `fetch` + ReadableStream

**实现位置**：
- 后端：`src/gateway/chat-stream-routes.ts` 的 `POST /api/v1/chat/stream`
- 前端：`web/lib/sse-client.ts`

**关键代码**：
```typescript
// 后端：流式返回 SSE
for await (const event of runAgentLoopStream(input)) {
  ctx.res.write(`event: ${event.type}\ndata: ${JSON.stringify(event)}\n\n`);
}
```

**验收**：
- 问 AI 一个长问题
- 前端 UI 上一字一字显示，不是等 3 秒后整段出现
```

然后在 15-开发进度计划.md 的 Step 5 末尾加「涉及需求：B2 / B7」。

## 17.3 怎么新增一个开发步骤

**唯一位置**：`15-开发进度计划.md`

步骤：

1. 找到合适位置（一般插在相关步骤之后）
2. 按下面模板写
3. 在末尾的「完成度追踪」表加一行
4. 涉及需求引用 16

- [ ] {项 1}

## 17.5 状态追踪

每个文档 / 步骤 / 需求都可以标状态：

| 状态 | 标记 | 含义 |
|------|------|------|
| 未开始 | ⬜ | 文档 / 代码都还没动 |
| 进行中 | 🔄 | 正在改文档 / 写代码 |
| 已完成 | ✅ | 写完且通过验收 |

### 用法

- `15-开发进度计划.md` 末尾「完成度追踪」表：每个 Step 一行
- `16-需求技术对照表.md` 也可以加「实施状态」列
- 状态变更时：改 `⬜` 为 `🔄` 或 `✅`，并填完成日期

## 17.6 文档版本约定

- **大改一次**：在文档末尾加一行 `> 最后更新：YYYY-MM-DD`
- **git commit message** 用 Conventional Commits（`feat:` / `fix:` / `docs:` / `refactor:` 等）
- **不删旧内容** —— 改错了 git history 还能找回来
- **新加内容** 优先在「扩展点」追加，不重写已有部分

## 17.8 变更同步规则（**最重要 · 文档 = 系统规格**）

> **核心原则**：这份文档**不是**写完就完的「实施说明」，**而是**整个系统的**「规格定义」——文档改了，代码必须跟；代码改了，文档必须跟。
> 文档和代码是 **1:1 镜像关系**，任何一边脱节都是 bug。

### 17.8.1 改 X → 必须同步改 Y（按场景分）

| 我改了... | 必须同步改的文档 | 不改会出问题 |
|----------|-----------------|------------|
| **加新需求 / 改需求描述** | ① `16-需求技术对照表.md`（**需求清单唯一入口**）<br>② `15-开发进度计划.md`（标涉及哪些 Step）<br>③ `04-UI需求.md`（如有 UI 影响）<br>④ `05-数据模型.md`（如有表结构变化）<br>⑤ `13 / 14-代码示例.md`（如需新代码模式） | 需求没地方看 / Step 不一致 / 数据表少字段 |
| **改 SQL 表结构（加字段 / 改类型）** | ① `05-数据模型.md`（DDL）<br>② `16-需求技术对照表.md`（如影响某条需求的字段）<br>③ `13-后端代码示例.md`（Sequelize 模型同步） | 表跟需求对不上 / 代码用了不存在的字段 |
| **改 / 加 API 端点** | ① `06-API接口.md`<br>② `13-后端代码示例.md`（路由代码）<br>③ `14-前端代码示例.md`（Axios 调用）<br>④ `16-需求技术对照表.md`（如对应新需求） | 前端调不存在的端点 / 后端写不存在的路由 |
| **加新 UI 页面 / 改 UI** | ① `04-UI需求.md`<br>② `14-前端代码示例.md`<br>③ `16-需求技术对照表.md`（如对应新需求）<br>④ `12-部署运维与成本.md`（如涉及端口） | UI 长什么样文档不写 / 前端代码跟设计稿对不上 |
| **改技术选型 / 换库** | ① `03-技术栈与规范.md`<br>② `13-后端代码示例.md` / `14-前端代码示例.md`（API 变了）<br>③ `16-需求技术对照表.md`（对应需求的技术）<br>④ `08-24模块知识点映射.md`（涉及哪个模块） | 代码用了不存在的库 / 文档不告诉后人选了啥 |
| **加新开发 Step** | ① `15-开发进度计划.md`（增加 Step + 完成度表）<br>② `16-需求技术对照表.md`（涉及需求）<br>③ `13 / 14-代码示例.md`（新增代码模式） | 进度表对不上 / 代码没参考 |
| **改部署 / 启动方式** | ① `12-部署运维与成本.md`<br>② `02-系统架构与目录.md`（架构图）<br>③ `16-需求技术对照表.md`（涉及 D5） | 起不来 / 架构图对不上 |
| **改观测 / 安全 / 评测** | ① `10 / 11 / 09-*.md`<br>② `16-需求技术对照表.md`<br>③ `13-后端代码示例.md` | 实际跑的对不上文档 |

### 17.8.3 文档 ↔ 代码对照（快速验证两边一致）

> 每次发版前跑一遍这个表，确保文档和代码没脱节。

| 检查项 | 文档 | 代码 | 怎么验 |
|--------|------|------|--------|
| 需求数 | `16-需求技术对照表.md` 列了 21 条 | 代码里都实现了 | 搜索「A1 / A2 / ...」代码引用 |
| 表数 | `05-数据模型.md` 列了 17 张 | Sequelize 模型都建了 | `ls src/models/*.ts` |
| API 数 | `06-API接口.md` 列了 23 个 | Koa 路由都建了 | `grep -r "router\." src/gateway/` |
| LLM 流式 | `04-UI需求.md §4.10` 用 Vercel AI SDK | `streamText()` + `useChat()` | 搜索 `streamText` / `useChat` |
| 数据库 | MySQL 8.0（`03`） | `mysql2` 驱动 | `package.json` |
| 鉴权 | JWT + bcrypt | `jsonwebtoken` + `bcrypt` | `package.json` |
| UI 框架 | Ant Design 5（`04`） | `antd` v5 | `package.json` |

### 17.8.4 「文档先行」原则

> **任何改动都先改文档，再改代码**。理由：
> 1. 文档是「规格」，代码是「实现」——规格错了实现就错
> 2. 改文档时容易发现需求漏洞；直接改代码容易埋雷
> 3. 改完文档后写代码，可以照着文档测试（**测试 = 文档自检**）

工作流：

```
1. 改 16-需求技术对照表.md
   ↓
2. 改 05-数据模型.md（如有表结构）
   ↓
3. 改 04-UI需求.md（如有 UI）
   ↓
4. 改 06-API接口.md（如有 API）
   ↓
5. 改 15-开发进度计划.md（更新 Step / 完成度）
   ↓
6. 改 13 / 14-代码示例.md（如需新代码模式）
   ↓
7. 改 README.md（如新增文件）
   ↓
8. 跑「变更检查清单」打钩
   ↓
9. 改代码
   ↓
10. git commit
```

## 17.9 命名 / 格式约定

- **文件编号**两位数字（`01` 到 `17`），新增文件用下一个编号
- **需求编号**：字母 + 数字（A1 / B2 / ...）
- **Step 编号**：连续整数（Step 1 / 2 / ...）
- **模块编号**：两位数字 `00`-`23`（已学模块），`AI-N`（新模块）
- **代码示例**用 TypeScript（前后端都用）
- **日志 / 注释**用完整中文，不用黑话缩写
- **跨文件引用**：写「`16-需求技术对照表.md`」，**不要**写相对路径 `[16](./16-...md)`（避免拷贝时失效）

> **核心原则**：
> - **需求清单只在 16 一份**

> - **状态显式标**，进度一目了然
> - **文档 = 系统规格，代码 = 镜像**——**改一边必须同步另一边**
