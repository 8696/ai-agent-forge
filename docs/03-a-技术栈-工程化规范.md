### A.3 TypeScript 配置（双 tsconfig，路径别名分前后端）

```json
// tsconfig.json（后端）
{
  "compilerOptions": {
    "target": "ES2023",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "lib": ["ES2023"],
    "types": ["node"],
    "outDir": "./dist",
    "rootDir": "./src",
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "noImplicitOverride": true,
    "noFallthroughCasesInSwitch": true,
    "exactOptionalPropertyTypes": true,
    "skipLibCheck": true,
    "esModuleInterop": true,
    "resolveJsonModule": true,
    "isolatedModules": true,
    "verbatimModuleSyntax": true,
    "paths": {
      "@shared/*": ["./shared/*"]
    }
  },
  "include": ["src/**/*", "shared/**/*"]
}

// tsconfig.web.json（前端）
{
  "extends": "./tsconfig.json",
  "compilerOptions": {
    "lib": ["DOM", "DOM.Iterable", "ES2023"],
    "types": ["vite/client"],
    "jsx": "react-jsx",
    "noEmit": true,
    "paths": {
      "@/*": ["./web/*"],
      "@shared/*": ["./shared/*"]
    }
  },
  "include": ["web/**/*", "shared/**/*"]
}
```

> **为什么 web/ shared/ 还要各放一个 tsconfig.json**：
>
> - WebStorm / VS Code 打开 `web/**/*.tsx` 时会向上找最近的 `tsconfig.json`，命中根目录那份（不带 JSX）会报 `TS6142: --jsx is not set`
> - 在 `web/` 和 `shared/` 下各放一个就近的 `tsconfig.json`（`web/` 那个 extends `./tsconfig.web.json`，`shared/` 那个 extends `./tsconfig.json`），IDE 就能解析到带 JSX / DOM lib 的正确配置
> - 实际构建仍走根目录 `tsc --noEmit -p tsconfig.web.json`，新增的子配置**不参与**构建，只给 IDE 用

### A.12 环境变量校验（启动时挂）

不在运行中才发现缺变量。`src/config.ts` 用 Zod 校验，缺必填项直接挂：

```typescript
// src/config.ts
import { z } from 'zod';

const envSchema = z.object({
  NODE_ENV: z.enum(['development', 'production', 'test']).default('development'),
  PORT: z.coerce.number().default(3000),

  // 数据库
  MYSQL_HOST: z.string().default('localhost'),
  MYSQL_PORT: z.coerce.number().default(3306),
  MYSQL_USER: z.string().default('root'),
  MYSQL_PASSWORD: z.string().default(''),
  MYSQL_DB: z.string().default('agent_platform'),

  // Qdrant
  QDRANT_URL: z.string().default('http://localhost:6333'),

  // LLM（Anthropic 协议）
  ANTHROPIC_API_KEY: z.string().min(1, 'ANTHROPIC_API_KEY 不能为空'),
  ANTHROPIC_BASE_URL: z.string().url().optional(),

  // JWT
  JWT_SECRET: z.string().min(32, 'JWT_SECRET 至少 32 字符'),
  JWT_EXPIRES_IN: z.string().default('7d'),

  // Embedding
  EMBEDDING_API_KEY: z.string().optional(),
  EMBEDDING_BASE_URL: z.string().url().optional(),
});

export const config = envSchema.parse(process.env);
```

### A.13 错误处理约定

自定义错误类 + Result 类型，两套并行用：

```typescript
// src/lib/errors.ts
export class AppError extends Error {
  constructor(
    message: string,
    public readonly code: string,
    public readonly statusCode: number = 500,
    public readonly details?: unknown,
  ) {
    super(message);
    this.name = 'AppError';
  }
}

export class ValidationError extends AppError {
  constructor(message: string, details?: unknown) {
    super(message, 'VALIDATION_ERROR', 400, details);
  }
}

export class NotFoundError extends AppError {
  constructor(resource: string) {
    super(`${resource} not found`, 'NOT_FOUND', 404);
  }
}

export class AuthError extends AppError {
  constructor(message = 'Unauthorized') {
    super(message, 'AUTH_ERROR', 401);
  }
}
```

Koa 中间件统一捕获：

```typescript
// src/gateway/error-handler.ts
import { AppError } from '@/lib/errors';

export async function errorHandler(ctx: any, next: any) {
  try {
    await next();
  } catch (err) {
    if (err instanceof AppError) {
      ctx.status = err.statusCode;
      ctx.body = { code: err.code, message: err.message, details: err.details };
      return;
    }
    // 未捕获错误：500 + 记录 trace
    ctx.status = 500;
    ctx.body = { code: 'INTERNAL_ERROR', message: 'Server error' };
    console.error(err);
  }
}
```

约定：

- **业务错误**用 `AppError` 子类（带状态码）
- **未知错误**走兜底 500，**不要**直接 `ctx.body = err.message`（会泄露内部信息）
- **Zod 校验失败** → 抛 `ValidationError`，自动 400

### A.14 Conventional Commits 提交示例

```bash
# 新功能
git commit -m "feat: 加入 SSE 流式聊天支持"

# 修复 bug
git commit -m "fix: 修复会话历史 token 超限导致的崩溃"

# 文档
git commit -m "docs: 补充 14-前端代码示例"

# 重构（不改行为）
git commit -m "refactor: 把 trace 写入拆成独立中间件"

# 性能优化
git commit -m "perf: 给 messages 表加 idx_messages_tenant_created 索引"

# 测试
git commit -m "test: 补 Agent loop 的单元测试"
```

格式：`<type>: <中文一句话>`。type 必须是 `feat` / `fix` / `docs` / `style` / `refactor` / `perf` / `test` / `build` / `ci` / `chore` / `revert` 之一。

### A.15 目录约定（barrel exports）

每个 `src/<module>/` 都得有一个 `index.ts`，对外只导出这一个文件：

```typescript
// src/agent-orchestrator/index.ts
export { runAgentLoop } from './loop';
export { runSupervisor } from './supervisor';
export type { AgentInput, AgentOutput } from './types';
// 内部文件（loop.ts / supervisor.ts / types.ts）不直接被外部 import
```

```typescript
// 引用
import { runAgentLoop } from '@/agent-orchestrator'; // ✅ 通过 barrel
// import { runAgentLoop } from '@/agent-orchestrator/loop';  // ❌ 禁止
```

好处：模块内部文件可以随意重构（改名 / 拆文件 / 合文件），只要 `index.ts` 导出不变，外部代码不动。
