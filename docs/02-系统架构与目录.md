## 2.2 数据流（一次典型请求）

1. 用户从网页挂件发消息「我上周买的 X 怎么退款？」
2. 网关校验 JWT + 限流检查 → 路由到 `/api/chat` 路由
3. 路由同步处理（拆块 + Embedding + 入向量库），几秒后返回结果
4. Agent 编排层 worker 取出任务：
   - 监督者代理分析意图：「退款咨询 → 需要研究代理 + 操作代理」
   - 研究代理调 RAG 检索政策文档 → 拿到退款政策片段
   - 操作代理调 MCP 订单查询工具 → 拿到该用户的最近订单
   - 客服代理综合两者，生成最终回复（含退款步骤、订单号、原文引用）
5. 审核代理检查回复是否含敏感信息 → 通过
6. 观测层全程记录：每一步的输入 / 输出 / token / 耗时 / 工具调用
7. 回复通过 SSE（Server-Sent Events）推送给前端
8. 用户看到回复，可继续追问

## 2.3 目录结构

> 项目以**后端为主**，前端为辅。`src/` 放后端代码，`web/` 放前端代码，根目录统一管理配置和工具链。
> 这里只规定项目顶层；`src/` 和 `web/` 的内部细化见本项目的「技术栈与规范」那一节（§6.4 / §7.2）。

```
project-A/
├── package.json              # 整个项目只这一个 package.json
├── tsconfig.json             # 后端 TypeScript 配置（strict mode）
├── tsconfig.web.json         # 前端 TypeScript 配置（strict mode + JSX）
├── vite.config.ts            # 前端构建（Vite 5，含 dev proxy）
│
├── eslint.config.js          # ESLint 9 flat config（前后端共用）
├── .prettierrc.json          # Prettier 3 配置
├── .editorconfig             # 编辑器基础规范（缩进 / 换行 / 文件末尾）
├── .lintstagedrc.json        # pre-commit 只对暂存文件跑检查
├── commitlint.config.js      # 提交信息按 Conventional Commits 规范
├── .husky/                   # Git hooks（pre-commit 跑 lint + typecheck）
│
├── index.html                # Vite 入口
├── .env.example              # 环境变量模板
├── docker-compose.yml        # 本地中间件（MySQL / Qdrant）
├── README.md
│
├── src/                      # ★ 后端代码（Node 22 + Koa + TypeScript）
│                             #   内部模块拆分见 03-技术栈与规范.md §6.4
│
├── web/                      # 前端代码（Vite + React 18 + Ant Design）
│                             #   内部结构见 03-技术栈与规范.md §7.2
│
├── shared/                   # 前后端共用的代码（types / prompts / schemas）
│
├── data/                     # 本地数据（uploads / qdrant-snapshot / mysql 卷）
├── logs/                     # 运行日志
└── scripts/                  # 辅助脚本（migrate / seed / eval-gen）
```

> **拷贝文档时的最小落地形态**：照上面建一个空目录，按 `yarn install` + `cp .env.example` + `yarn dev` 起项目。`src/` / `web/` / `shared/` 内部的细化按本项目的「技术栈与规范」那一节 §6.4 / §7.2 填。
