### A.13 错误处理约定

自定义错误类 + Result 类型，两套并行用：

```typescript
// src/lib/errors.ts
export class AppError extends Error {
  constructor(
    message: string,
    public readonly code: string,
    public readonly statusCode: number = 500,
    public readonly details?: unknown
  ) {
    super(message);
    this.name = 'AppError';
  }
}

export class ValidationError extends AppError {
  constructor(message: string, details?: unknown) {
    super(message, 'VALIDATION_ERROR', 400, details);
  }
}

export class NotFoundError extends AppError {
  constructor(resource: string) {
    super(`${resource} not found`, 'NOT_FOUND', 404);
  }
}

export class AuthError extends AppError {
  constructor(message = 'Unauthorized') {
    super(message, 'AUTH_ERROR', 401);
  }
}
```

Koa 中间件统一捕获：

```typescript
// src/gateway/error-handler.ts
import { AppError } from '@/lib/errors';

export async function errorHandler(ctx: any, next: any) {
  try {
    await next();
  } catch (err) {
    if (err instanceof AppError) {
      ctx.status = err.statusCode;
      ctx.body = { code: err.code, message: err.message, details: err.details };
      return;
    }
    // 未捕获错误：500 + 记录 trace
    ctx.status = 500;
    ctx.body = { code: 'INTERNAL_ERROR', message: 'Server error' };
    console.error(err);
  }
}
```

约定：

- **业务错误**用 `AppError` 子类（带状态码）
- **未知错误**走兜底 500，**不要**直接 `ctx.body = err.message`（会泄露内部信息）
- **Zod 校验失败** → 抛 `ValidationError`，自动 400

### A.15 目录约定（barrel exports）

```typescript
// src/agent-orchestrator/index.ts
export { runAgentLoop } from './loop';
export { runSupervisor } from './supervisor';
export type { AgentInput, AgentOutput } from './types';
// 内部文件（loop.ts / supervisor.ts / types.ts）不直接被外部 import
```

```typescript
// 引用
```

## B. 后端技术栈

### B.1 语言与运行时

| 选型 | 版本 | 理由 |
|------|------|------|
| Node.js | 22 LTS | 当前 LTS 版本；原生 fetch、内置测试运行器、性能比 20 LTS 提升 ~20% |
| TypeScript | 5.6 | 类型安全；strict mode + 几条额外严格项 |
| yarn | 1.22 | lockfile 稳定、磁盘占用小 |

### B.2 框架

| 模块 | 选型 | 理由 |
|------|------|------|
| HTTP 服务 | Koa | 洋葱中间件模型、生态成熟、TypeScript 友好；Express 继任者 |
| Agent 编排 | 手写循环 + LangGraph | 手写为主，复杂工作流用 LangGraph |
| ORM | Sequelize | 老牌成熟、迁移工具稳、社区文档全 |
| 校验 | Zod | 类型 + 运行时校验同源 |
| 日志 | Pino | 高性能 JSON 日志 |
| 链路追踪（自建） | `tracer.startActiveSpan`-style + 写 MySQL | 自建轻量版，够本地用；要扩展时再上 OpenTelemetry |

### B.3 中间件

| 中间件 | 选型 | 用途 | 本地起在哪 |
|--------|------|------|------------|
| 数据库 | MySQL 8.0 | 业务数据；JSON 字段、半结构化数据存 MySQL JSON 类型 | Docker Compose |
| 向量库 | Qdrant | 向量检索（RAG 基础 + 重排） | Docker Compose |
| 对象存储 | 本地 `./data/uploads/` | 上传的文档原文件 | 本地磁盘 |
| 链路追踪 | 自建文件（写到 `logs/trace-YYYY-MM-DD.jsonl`） | 调用链路记录，trace 数据存 MySQL + 文件双写 | 本地文件 |
| 缓存 | 进程内 `lru-cache` | 文档检索结果缓存（可选，单进程够用） | 进程内存 |

> **不引入 Redis**（当前规模用不上）。将来要扩展（多进程 / 海量消息 / 大文件异步处理）再加 Redis + BullMQ。短期对话记忆查 MySQL 即可，每次请求多一次 SELECT 完全 OK。

### B.4 后端模块拆分（src/ 内部）

```
src/
├── server.ts                # 后端入口（监听 localhost:3000）
├── gateway/                 # 网关：鉴权、限流、路由
├── agent-orchestrator/      # Agent 编排：监督者 + 子代理 + 共享状态
├── rag/                     # RAG：分块、embedding、向量检索、重排序
├── tools/                   # 工具调用 + MCP 适配
├── memory/                  # 短期 + 长期记忆
├── workflow/                # 工作流：状态机 + 人工审批
├── moderation/              # 内容审核
├── evaluation/              # 评测 + 大模型当裁判
├── observability/           # trace + metric + log
└── admin/                   # 运营后台 API
```

| 模块 | 职责 | 关键依赖 |
|------|------|----------|
| `gateway/` | 鉴权、限流、域名路由、CORS、请求日志 | JWT、进程内 Map（限流） |
| `agent-orchestrator/` | 监督者 + 子代理 + 共享状态 | LLM API、记忆、观测 |
| `rag/` | 文档分块、embedding、向量检索、重排序 | Qdrant、Embedding API |
| `tools/` | 工具注册、调用、结果解析；MCP 客户端 | LLM API、MCP SDK |
| `memory/` | 短期对话 + 长期用户偏好 + 摘要压缩 | MySQL（短期历史查 messages，长期偏好存 users.preferences） |
| `workflow/` | 任务状态机 + 人工审批节点 | MySQL、SSE（本项目 Phase 1 仅简单状态，无 HITL） |
| `moderation/` | 输入审核（注入检测）+ 输出审核（敏感词） | 审核 API、本地规则 |
| `evaluation/` | 评测集管理 + 大模型当裁判 + A/B 对比 | MySQL、LLM API |
| `observability/` | trace + metric + log | Pino、自建 trace（不上 OpenTelemetry） |
| `admin/` | 运营后台 API：租户管理、用户管理、配置管理 | MySQL |

> 每个模块对应 `src/<name>/index.ts` 主入口 + 内部拆分的若干文件。模块之间通过 `import { Agent } from '@/agent-orchestrator'` 互相调用，禁止循环依赖（用单向数据流）。

## C. 前端技术栈

### C.1 框架与库

| 选型 | 用途 | 理由 |
|------|------|------|
| Vite 5 | 构建工具 + 开发服务器 | 启动秒开；HMR 快；纯客户端渲染，没有 SSR |
| React 18 | 视图层 | 函数组件 + Hooks；AntD 配套 |
| TypeScript | 类型 | 与后端共用类型 |
| **Ant Design 5** | 组件库 | 国内业务后台首选；组件齐全（Table / Form / Modal / Layout 全有）；支持主题定制 |
| React Router DOM 6 | 路由 | 客户端路由；管理后台的菜单跳转 |
| Axios | HTTP 请求 | 拦截器统一处理鉴权、错误 |
| Zustand | 客户端状态 | 比 Redux 轻 |
| Day.js | 时间处理 | AntD v5 配套（AntD 已不内置 moment） |
| `@ant-design/icons` | 图标 | AntD 官方图标库 |

**为什么选 AntD 而不是 shadcn/ui / Tailwind**：

- 组件齐全：管理后台要用的 Table、Tree、Transfer、Cascader、Form、Drawer，AntD 一个包搞定；用 shadcn/ui 要拼 Radix + Tailwind + 一堆插件
- 中文文档 + 中文社区：国内项目，搜「AntD 表格分页」能直接找到答案
- 主题按品牌定制：`ConfigProvider` 改 token，整个应用的色调、字号、圆角一起改

### C.6 聊天挂件的特殊处理

聊天挂件是嵌入客户网站的小窗口，跟管理后台是同一份前端代码，但走不同入口：

- 挂件走 `/widget/:tenantId`，加载极简样式（AntD 主题临时覆盖为紧凑版）
- 挂件状态靠 URL 传 tenant，**不做鉴权**（公开）
- 挂件内不显示管理后台导航
