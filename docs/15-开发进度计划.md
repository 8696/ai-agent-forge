## Step 1 · 工程骨架

**目标**：后端服务能起、能响应健康检查；docker compose 起中间件；工程化规范配齐。

**涉及需求**：A1（部分：tenants / users 表结构）

**交付物**：

- [ ] Node 22 + TypeScript 5.6 + yarn 1.22 工程初始化
- [ ] Koa + koa-bodyparser + koa-cors 起服务，监听 3000
- [ ] Sequelize + mysql2 + sequelize-typescript 接入
- [ ] docker-compose 起 MySQL 8.0 + Qdrant
- [ ] vitest.config.ts + ESLint 9 flat config + Prettier 3 + lint-staged + Husky + commitlint 配齐
- [ ] `tenants` / `users` 表的 Sequelize 模型 + 迁移
- [ ] `GET /health` 返回 200
- [ ] `src/config.ts` 用 Zod 校验环境变量

**验收**：`yarn dev`，curl `http://localhost:3000/health` 返回 `{ ok: true }`。

## Step 2 · 多租户 + 用户管理

**目标**：SaaS 平台方能创建租户 + 初始化 admin；租户 admin 能管本租户用户。

**涉及需求**：A1（数据隔离）/ A2（建租户初始化 admin）/ A3（用户管理）

**交付物**：

- [ ] `tenants` 表加 `code` 字段（UNIQUE 索引）
- [ ] `system_users` 表（SaaS 平台方账号）
- [ ] `api_keys` 表（租户 API 密钥）
- [ ] `POST /api/v1/system/tenants`（事务里建 tenant + 初始 admin）
- [ ] `GET /api/admin/users`（列当前租户用户）
- [ ] `POST /api/admin/users`（admin 创建后台 / 前台用户）
- [ ] `PATCH /api/admin/users/:id`（改邮箱 / 重置密码）
- [ ] `DELETE /api/admin/users/:id`
- [ ] `POST /api/v1/auth/change-password`（首次登录强制改）

**验收**：手动 SQL 插入一个「SaaS 平台方」账号 → 通过 API 创建租户「acme-corp」+ 初始 admin → 登录进 `/admin` → 创建 3 个前台用户。

## Step 3 · 三层登录 + 鉴权

**目标**：3 个登录入口都能登；JWT 串起来后续所有受保护接口；防暴力破解。

**涉及需求**：A4（三层登录 + 租户号必填）

**交付物**：

- [ ] `POST /api/v1/system/login`（SaaS 平台方，不要租户号）
- [ ] `POST /api/v1/auth/login`（后台 / 前台，**必填 tenant_code + login_type**）
- [ ] `GET /api/v1/auth/me`
- [ ] bcrypt 密码哈希（cost=12）
- [ ] JWT 签发 + 验证中间件（payload: `{ sub, tenant_id, role }`）
- [ ] 错误响应统一 `401 邮箱或密码错误`（防账号枚举）
- [ ] 登录失败次数 + 账号锁定（`users.failed_login_count` + `locked_until`）
- [ ] P-L1 / P-L2 / P-L3 三个登录页面（AntD Form + tenant_code 输入框）

**验收**：SaaS 平台方登录 → 创建租户 → 租户 admin 登录（带 tenant_code）→ 改密码 → 创建前台用户 → 前台用户登录（带 tenant_code）。

## Step 4 · 知识库管理

**目标**：租户 admin 能上传文档；自动拆块 + Embedding + 入向量库；检索测试能用。

**涉及需求**：C1（知识库管理）

**交付物**：

- [ ] `documents` 表 + `documents` Sequelize 模型 + 迁移
- [ ] `POST /api/admin/knowledge/upload`（@koa/multer 处理 PDF / Word / MD / TXT）
- [ ] 文档落地到 `./data/uploads/{tenant_id}/{nanoid}.{ext}`
- [ ] 拆块（chunk_size=800, overlap=150）
- [ ] Embedding 调用（独立 REST 客户端）
- [ ] 入 Qdrant（按 `tenant_id` metadata 过滤）
- [ ] **同步处理**：上传后 API 直接跑分块 + Embedding + 入向量库，几秒后返回
- [ ] `documents.status` 流转：`uploaded → indexing → ready / failed`
- [ ] P8 后台「知识库管理」页面（文档列表 + 上传 + 状态显示）
- [ ] 检索测试 API + P-检索测试 页面（admin 输入问句 → 看 top 5 命中的片段）

**验收**：上传一个 .md 文件 → 列表显示状态 `uploaded` → 几秒后变 `ready` → Qdrant 里能查到向量 → 检索测试能命中。

## Step 5 · RAG 检索

**目标**：混合检索 + 重排序；为 LLM 提供高质量的上下文。

**涉及需求**：B2（RAG 检索）

**交付物**：

- [ ] 向量检索封装（`src/rag/search.ts`）：query → embedding → Qdrant 查 top-K
- [ ] BM25 关键词检索（`src/rag/bm25.ts`）
- [ ] RRF 融合（BM25 + 向量结果）
- [ ] 重排序（`src/rag/rerank.ts`）：bge-reranker-v2-m3
- [ ] `src/rag/hybrid-search.ts`：对外统一接口

**验收**：单跑 `hybridSearch('年假几天', tenantId, topK=5)` → 返回 5 个带相似度分数的片段；BM25 命中「年假」、向量命中语义相近段落。

## Step 7 · 多轮对话 + 历史

**目标**：用户连问 N 轮，AI 记得；每条消息入库；前后台都能看历史。

**涉及需求**：B1（多轮对话 + 上下文窗口）/ B4（短期记忆）

**交付物**：

- [ ] `sessions` / `messages` 表 + 模型 + 迁移
- [ ] `messages.thinking_content`（思考模式单独存）
- [ ] `messages.status` (`streaming` / `complete` / `failed` / `cancelled`)
- [ ] `messages.usage` (input_tokens / output_tokens / cache_read_tokens)
- [ ] `messages.trace_id`（关联到 traces）
- [ ] `messages.feedback` (1 / -1 / NULL) + `feedback_text` + `feedback_at`
- [ ] `sessions.title`（第一条用户消息前 20 字）/ `summary`（摘要压缩用）
- [ ] Token 预算配置（`src/lib/token-budget.ts`）
- [ ] 上下文窗口管理：超出 token 预算自动摘要压缩早期内容
- [ ] Anthropic Prompt Caching（`cacheControl: { type: 'ephemeral' }`）
- [ ] `GET /api/v1/sessions/:id`（前台用户看自己的历史）
- [ ] 后台 `GET /api/admin/sessions`（admin 看租户所有用户的历史）

**验收**：连问 5 轮，AI 记得前几轮；messages 表每条都入库；后台能看完整 session。

## Step 11 · 观测 + 成本

**目标**：每次请求能看到 trace + token + 成本；超阈值告警。

**涉及需求**：D2（可观测性）/ D3（成本控制）

**交付物**：

- [ ] `traces` / `spans` 表 + 模型 + 迁移
- [ ] 自建 trace 包装器（`src/observability/trace.ts`）：每个 span 写 MySQL
- [ ] 关键 span：HTTP 请求 / Agent 步骤 / LLM 调用 / 工具调用
- [ ] span 属性：user_id / session_id / tenant_id / step_name / input_tokens / output_tokens / duration_ms / cost
- [ ] trace 数据双写：MySQL + `logs/trace-YYYY-MM-DD.jsonl`
- [ ] Pino 结构化日志 → `./logs/app-YYYY-MM-DD.log`
- [ ] 每租户 token 配额（`tenants.settings.monthly_token_budget`）
- [ ] 进程内 Map 累计每月 token
- [ ] 超阈值告警（控制台告警条 + `audit_logs`）
- [ ] P4 后台「Trace 详情」页面（时间线 + 单步详情）
- [ ] P5 后台「成本分析」页面（按用户 / 场景拆解）

**验收**：前台发个请求 → 后台 P4 看到完整调用链路 + token + 成本；P5 看今天的成本曲线；超阈值后告警条出现。

## Step 12 · 安全 + 可靠性

**目标**：不能被攻击（注入 / 审核 / 脱敏）；不能挂（限流 / 熔断 / 审计）。

**涉及需求**：D4（安全防护）/ D5（可靠性 + 审计）

**交付物**：

- [ ] 注入检测（规则匹配 + 大模型二次确认）
- [ ] 输入审核：敏感词库（暴力 / 色情 / 政治）
- [ ] 输出审核：模型回复先过大模型
- [ ] 敏感数据脱敏：身份证 / 银行卡 / 手机号正则替换
- [ ] 限流：进程内 `Map<key, {count, windowStart}>`（按租户 / IP / 接口）
- [ ] 熔断：连续失败 N 次短路
- [ ] 重试：LLM 调用失败指数退避 + 抖动
- [ ] `audit_logs` 表 + 自动写所有关键操作
- [ ] 进程内 `lru-cache` 缓存（可选，相同问题直接返回缓存）

**验收**：压测 + 异常输入 → 注入检测挡掉；连续触发限流后被拒绝；所有关键操作（建用户 / 改配置 / 登录失败）→ audit_logs 有记录。
