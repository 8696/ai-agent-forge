## A · 多租户基础

### A1 · 多租户数据隔离

**需求**：每个租户数据严格隔离，查询不跨租户。

**对应 Step**：Step 1 / Step 2

**使用技术**：

- MySQL 8.0（InnoDB 引擎、utf8mb4 字符集）
- Sequelize 6.x + sequelize-typescript（装饰器风格）
- 模型层 scope + beforeFind hook（自动加 tenant_id 过滤）

**实现位置**：

- 数据模型：`05-a-数据模型-mysql.md` §5.1 每张业务表都有 `tenant_id` 字段 + 索引
- 模型定义：`src/models/Document.ts` / `Session.ts` / `Message.ts` / `User.ts` 等
- 仓储层：`src/repositories/document-repository.ts` 等

**关键代码**：

```typescript
// src/models/Document.ts
@Table({ tableName: 'documents', timestamps: true })
@Scopes(() => ({
  // 自动加 tenant_id 过滤（注入当前用户所属的 tenant_id）
  forTenant: (tenantId: string) => ({
    where: { tenant_id: tenantId },
  }),
}))
export class Document extends Model {
  /* ... */
}

// 仓储层用法
export async function listDocuments(tenantId: string) {
  return await Document.scope('forTenant', tenantId).findAll();
}
```

**验收**：

- 建两个租户 T1 / T2，各传一份文档
- T1 admin 调 `listDocuments(T1)` 只能看到 T1 的文档
- 直接 `Document.findAll()`（不带 scope）应该有警告或被 lint 禁止

### A2 · SaaS 平台方建租户 + 自动初始化 admin

**需求**：SaaS 平台方建租户时自动写 `tenants` + 第一个 admin 账号。

**对应 Step**：Step 2 / Step 3

**使用技术**：

- Koa 路由（`POST /api/v1/system/tenants`）—— system 子系统前缀（详见 `03-b-技术栈-后端栈.md` §B.5）
- Sequelize 事务（`sequelize.transaction`）
- bcrypt 密码哈希（cost=12）
- Zod 校验租户号格式（`[a-z0-9-]{3,32}`）

**实现位置**：

- 路由：`src/gateway/system/tenant-routes.ts`（system 子系统目录）→ `POST /api/v1/system/tenants`
- 鉴权中间件：`src/gateway/system/middleware.ts` 的 `requireSystemUser`（JWT payload 必须是 `role='system'`）
- 模型：`src/models/Tenant.ts` + `src/models/User.ts`

**关键代码**：

```typescript
systemTenantRouter.post('/tenants', jwtAuth, requireSystemUser, async (ctx) => {
  const input = createTenantSchema.parse(ctx.request.body);
  const sequelize = getSequelize();

  const result = await sequelize.transaction(async (tx) => {
    const existing = await Tenant.findOne({ where: { code: input.code }, transaction: tx });
    if (existing !== null) {
      throw new ValidationError('租户号已被使用');
    }
    const tenant = await Tenant.create({ code: input.code, name: input.name }, { transaction: tx });
    const admin = await User.create(
      {
        tenant_id: tenant.id,
        email: input.admin_email,
        password_hash: await hashPassword(input.admin_password),
        role: 'admin',
        must_change_password: true, // 首次登录强制改
      },
      { transaction: tx },
    );
    return { tenant, admin };
  });

  ctx.body = {
    tenant: {
      id: result.tenant.id,
      code: result.tenant.code,
      name: result.tenant.name,
      plan: result.tenant.plan,
    },
    admin: {
      id: result.admin.id,
      email: result.admin.email,
      role: result.admin.role,
      must_change_password: result.admin.must_change_password,
    },
  };
});
```

**验收**：

- POST `/api/v1/system/tenants` 带正确 body → 返回租户 + admin 信息
- 数据库里 tenants 有 1 条新记录，users 有 1 条 `role='admin'` 的记录
- code 重复提交 → 返回 400 「租户号已被使用」
- **跨子系统鉴权**：用 `role='admin'` 的 token 调 → 401（`requireSystemUser` 直接拒）

### A3 · 后台用户管理（admin 子系统内部，含创建 customer）

**需求**：租户 admin 创建本租户内的用户——创建时可指定角色（admin 子系统入口可下发 admin / customer 两类用户）；列 / 改邮箱 / 重置密码 / 删全部限定在本租户范围内。

**对应 Step**：Step 2（后端）/ Step 13（P10 前端）

**使用技术**：

- Koa 路由（`POST /api/v1/admin/users` / `GET /api/v1/admin/users` / `PATCH /api/v1/admin/users/:id` / `DELETE /api/v1/admin/users/:id`）—— admin 子系统前缀
- bcrypt 密码哈希
- Zod 校验（`createUserSchema` 收 `role: 'admin' | 'customer'`；`roleSchema` 显式拒收 `agent`——`agent` 是历史 ENUM 值，MVP 不开放）
- **跨租户隔离**：`where: { tenant_id: ctx.state.adminUser.tenant_id }`（强制加过滤）
- **自删防御**：`DELETE /users/:id` 校验 `id !== ctx.state.adminUser.sub`，前端按 `me.sub === row.id` 把删除按钮 `disabled`

**实现位置**：

- 路由：`src/gateway/admin/user-routes.ts`（admin 子系统目录）
- 鉴权中间件：`src/gateway/admin/middleware.ts` 的 `requireAdmin`（JWT payload 必须是 `role='admin'`）
- Schema：`src/lib/validators.ts` 的 `createUserSchema` / `updateUserSchema`（后者不收 `role`，所以编辑流程只改邮箱 + 重置密码，角色一旦创建不可改）
- 模型：`src/models/User.ts`（DB ENUM 含 `agent` 是历史遗留，validator 不放行）

**关键代码**：

```typescript
adminUserRouter.post('/users', jwtAuth, requireAdmin, async (ctx) => {
  const u = ctx.state.adminUser; // 从 JWT 取，已经 requireAdmin 收窄到 role='admin'
  const input = createUserSchema.parse(ctx.request.body);
  // createUserSchema: { email, password(min 8), role: 'admin'|'customer' }

  if (await User.findOne({ where: { email: input.email, tenant_id: u.tenant_id } })) {
    throw new ValidationError('邮箱已存在');
  }

  const user = await User.create({
    tenant_id: u.tenant_id, // 跨租户防御：强制从 token 取，不接受 body
    email: input.email,
    password_hash: await hashPassword(input.password),
    role: input.role, // 'admin' / 'customer' 二选一；agent 在 createUserSchema 里被拒
  });

  ctx.body = {
    id: user.id,
    email: user.email,
    role: user.role,
    must_change_password: user.must_change_password,
  };
});
```

**验收**：

- admin 在 P10 创建 3 个 admin 角色用户（实际业务：不同 admin 共存）
- admin 在 P10 创建 2 个 customer 角色用户（前台用户由租户后台代建；不再只能 customer 自注册）
- 三个用户分别能从 `/admin/login`（admin）或 `/customer/login`（customer）登录（同租户号 + 不同邮箱）
- 跨租户创建用户被禁止（`tenant_id` 永远从 token 拿，不接受 body）
- 自删防御：admin 在 P10 列表点自己的「删除」按钮 → 按钮 disabled；直接调 API 也返回 400「不能删除自己」

### A4 · 三层登录 + 鉴权（每套子系统自闭环）

**需求**：3 个登录入口（system / admin / customer），每个子系统自己一套 login / me / change-password，前后端 URL 前缀对齐。

**对应 Step**：Step 3

**使用技术**：

- Koa 路由（3 套独立端点，无共享 auth namespace）
- JWT（`jsonwebtoken`）：system 用 `{sub, role:'system'}`；admin/customer 用 `{sub, tenant_id, role}`
- bcrypt 密码哈希
- Zod 校验
- 5 次失败 → 锁定 15 分钟（`src/lib/login-lock.ts`）
- **统一 401 响应**（不区分「用户不存在」vs「密码错」，防账号枚举）

**实现位置**：

- 路由：
  - `src/gateway/system/auth-routes.ts`（system 子系统）
  - `src/gateway/admin/auth-routes.ts`（admin 子系统）
  - `src/gateway/customer/auth-routes.ts`（customer 子系统）
- 中间件：每个子系统各自的 `middleware.ts` 里的 `requireXxxUser`
- 鉴权 schema：`src/lib/validators.ts`

**关键代码**（customer 子系统，admin/system 类似）：

```typescript
// src/gateway/customer/auth-routes.ts
customerAuthRouter.post('/login', async (ctx) => {
  const input = CustomerLoginBody.parse(ctx.request.body); // {email, password, tenant_code}

  const tenant = await Tenant.findOne({ where: { code: input.tenant_code } });
  if (tenant === null) throw new AuthError('邮箱或密码错误');

  // 锁死在 customer 角色（admin 账号登不进 customer 端点）
  const user = await User.findOne({
    where: { email: input.email, tenant_id: tenant.id, role: 'customer' },
  });
  if (user === null) throw new AuthError('邮箱或密码错误');
  throwIfLocked(user);

  if (user.password_hash === null) throw new AuthError('邮箱或密码错误');
  const ok = await verifyPassword(input.password, user.password_hash);
  if (!ok) {
    await recordFailedLogin(user);
    throw new AuthError('邮箱或密码错误'); // 统一 401，防枚举
  }

  await recordSuccessfulLogin(user);
  const token = signToken({ sub: user.id, tenant_id: tenant.id, role: user.role });
  ctx.body = { token };
});
```

**端点清单**（按子系统分桶，URL 前缀对齐）：

| 子系统       | 端点                                    | 鉴权              | 角色     |
| ------------ | --------------------------------------- | ----------------- | -------- |
| **system**   | `POST /api/v1/system/login`             | 无                | —        |
| system       | `GET /api/v1/system/me`                 | requireSystemUser | system   |
| system       | `POST /api/v1/system/change-password`   | requireSystemUser | system   |
| **admin**    | `POST /api/v1/admin/login`              | 无                | —        |
| admin        | `GET /api/v1/admin/me`                  | requireAdmin      | admin    |
| admin        | `POST /api/v1/admin/change-password`    | requireAdmin      | admin    |
| **customer** | `POST /api/v1/customer/login`           | 无                | —        |
| customer     | `GET /api/v1/customer/me`               | requireCustomer   | customer |
| customer     | `POST /api/v1/customer/change-password` | requireCustomer   | customer |

> **反例**（禁止）：
>
> - ❌ `POST /api/v1/auth/login` + `login_type: 'admin' | 'customer'` 一个端点多种身份
> - ❌ 共享的 `change-password` 在 `/api/v1/auth/change-password`（两个子系统共用一个端点）

**验收**（19 个端到端用例，详见 `scripts/test-step3.ts`）：

- system 登录（正确 / 错密码 / 错邮箱 / 错误响应统一防枚举）= 4
- admin / customer 各自登录（正确 / 错租户号 / 错密码）= 6
- 跨子系统防御：admin 账号登 customer → 401；customer 账号登 admin → 401 = 2
- `/me` 各自端点正确（admin/customer 200，system 调 admin/me 401，admin 调 customer/me 401）= 4
- 5 次失败 → 锁定（DB 状态正确 + 正确密码也 401）= 2
- 成功后 failed_login_count 清零 = 1
- 改密码（admin 自己改 + 改后 /me 仍 OK）= 2

**前端对应**（详见 `03-b-技术栈-后端栈.md` §B.5）：

- `/system/login` → `SystemLoginPage` → 登录成功 → `/`
- `/admin/login` → `AdminLoginPage`（表单含 `tenant_code`）→ `/`
- `/customer/login` → `CustomerLoginPage`（表单含 `tenant_code`）→ `/`

根路径 `/` 用 `RootRedirect` 组件按当前 token 的 role 分流到对应首页。

**3 个登录页 + 3 个首页 + RequireAuth 守卫**（前端按 URL 前缀判断跳哪个登录页）。
