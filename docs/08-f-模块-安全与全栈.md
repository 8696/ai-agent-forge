### 模块 20 · AI 安全（AI Security）

**解决什么问题**：防止恶意用户通过提示词注入攻击系统、防止敏感数据泄露。

**用到的技术**：

- 提示词注入检测：检测用户输入是否试图覆盖系统提示
- 输入审核：暴力、色情、政治敏感
- 输出审核：模型回复是否泄露系统提示 / 工具内部信息
- 敏感数据脱敏：身份证、银行卡、手机号
- 工具调用权限：每个工具有允许的调用方

**关键代码**：

```typescript
// src/moderation/input-checker.ts
const INJECTION_PATTERNS = [
  /忽略之前的指令/i,
  /你现在是/i,
  /system\s*:/i,
  /<\|im_start\|>/i,
  // ... 更多模式
];

export async function checkInjection(input: string): Promise<{
  is_injection: boolean;
  confidence: number;
  reason?: string;
}> {
  // 1. 规则匹配
  for (const pattern of INJECTION_PATTERNS) {
    if (pattern.test(input)) {
      return { is_injection: true, confidence: 0.9, reason: 'pattern match' };
    }
  }

  // 2. 用大模型二次确认
  const result = await llm.generate({
    system: INJECTION_DETECTION_PROMPT,
    user: input,
    response_schema: z.object({
      is_injection: z.boolean(),
      confidence: z.number(),
    }),
  });
  return result;
}
```

### 模块 21 · 后端与基础设施

**解决什么问题**：把整套系统稳定地跑起来。

**用到的技术**：

- Docker Compose：MySQL / Qdrant 本地一键起
- 反向代理（开发期）：Vite dev proxy 把 `/api` 和 `/ws` 转给后端
- 数据持久化：MySQL 数据卷 `./data/mysql-data/`；Qdrant 数据卷 `./data/qdrant-snapshot/`
- 手动备份脚本：`mysqldump` + Qdrant snapshot + tar
- **不做**：CI/CD、云端部署、HTTPS、Kubernetes、异地备份

> 运维与部署细节见 `12-部署运维与成本.md`；MySQL 与 Qdrant 数据卷 / 备份策略见 `05-a-数据模型-mysql.md` §5.4 + `05-b-数据模型-qdrant.md` §5.6.5。

### 模块 23 · 整体架构

**解决什么问题**：把上面所有模块的取舍、依赖、演进路径讲清。

**架构图**：见本项目的「系统架构与目录」`02-系统架构与目录.md` §2.1。

**关键技术取舍**（ADR，架构决策记录）：

- 为什么选 Koa 而不是 Express（洋葱中间件模型更灵活、生态比 Express 新）
- 为什么选 MySQL 而不是 PostgreSQL（团队熟悉、运维成本低）
- 为什么选 Qdrant 而不是 Pinecone（成本 + 数据自主）
- 为什么手写 Agent 循环为主、LangGraph 为辅（可控性 + 学习价值）→ **本项目实际最终为 Vercel AI SDK**
- 为什么选本地 trace 文件而不是 Langfuse（不部署到云）
