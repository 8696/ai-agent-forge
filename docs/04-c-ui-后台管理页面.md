- 实现：`web/pages/admin/KnowledgeDocumentsPage.tsx`，数据来自 `GET /api/v1/admin/knowledge`
- **上传格式只支持 PDF / Markdown / TXT**（没有 DOCX，解析器没引 mammoth）。
  前端 `accept` + 后端扩展名校验双重拦截，非法扩展名返 400
- **上传是同步的**：后端在同一个请求里跑完「解析 → 拆块 → Embedding → 入库」，
  所以上传期间按钮转圈、进度条走 100% 常显；**一次只能传一个文件**，
  并发传不会更快，只会把 embedding 的限流打满
- 状态：`uploaded` → `indexing` → `ready` / `failed`；失败行显示红色「索引失败」，
  点进抽屉能看到 `error_message` 里的错误摘要
- 单击行 → 抽屉：文档 ID（可复制）/ 类型 / 状态 / 块数 / 上下行时间 + 「重新索引」按钮
- 4 张统计卡：「已索引块数」= 本租户 ready 文档的块数合计；
  「关键词索引块数」= BM25 内存索引，**服务重启后重建期间会偏低**，卡片上会挂一个「重建中」提示；
  「向量库总点数」是**跨租户**的，仅供运维参考
- 搜索 + 状态筛选 + 分页都在**服务端**做（`?page=&page_size=&keyword=&status=`）

### 5.3 检索测试 `/admin/knowledge/test`（★ 关键 · admin 最常用的功能）✅ 已落地

```
┌──────────────────────────────────────────────────┐
│  检索测试                                           │
│  验证知识库的召回效果：输入问句，看哪些文档块被检索    │
│  到、是被哪一路召回的。                               │
│  ┌─────────────────────────────────────────┐    │
│  │ 年假可以跨年结转吗？ 发票什么时候截止提交？ [🔍检索]│    │
│  └─────────────────────────────────────────┘    │
│  返回条数 [5]  两路召回：向量 + 关键词，RRF 融合排序   │
│                                                    │
│  ─── 命中 1 条 ──────────────────────────────     │
│  ┃ 1. 员工手册.md  第 1 块  [相关度 1.00]          │
│  ┃    [语义 第 1] [关键词 第 1]                    │
│  ┃    "Q：年假可以跨年结转吗？A：最多可结转 5 天…"  │
│  ┃    … 展开全文                                   │
└──────────────────────────────────────────────────┘
```

- 实现：`web/pages/admin/KnowledgeSearchPage.tsx`，调 `POST /api/v1/admin/knowledge/search`
- 输问句 → 混合召回 + RRF 融合 → 显示命中块；右上角显示本次耗时（ms）
- **这一页不调 LLM、不生成 AI 回答**。它的价值就是看清「哪些块被召回了、为什么」，
  加了 LLM 反而掩盖了检索层的问题。要看回答效果去前台聊天页
- 每条命中显示：文档名 + 块序号 + `相关度` + `语义第 N` / `关键词第 N` 两个排名标签 + 片段预览（可展开全文）
- 每条左侧有绿色/灰色竖条：绿色 = 两路都召回（说明向量和关键词都认为它相关）
- 空结果时提示「检查知识库是否有已就绪的文档，或换个说法再试」

> **score 怎么读**（`src/rag/hybrid-search.ts` 有完整推导）：
>
> - `hits[].score` 是**归一化到 [0,1]** 的 RRF 分：`1.0` = 向量 + 关键词两路都排第一；
>   只有一路排第一最高只能到 `0.5`。**这是设计如此，不是 bug** ——
>   归一化用的是「双路都第一」的理论满分 `2/(k+1)`，不是「本次最高分」。
>   早期设计稿里写的「按本次最高分归一化」会让任何一次检索的第一名都显示成 1.00，哪怕语料里根本没有相关文档。
> - `hits[].rrf_score` 是原始 RRF 分（k=60，单源最大 ~0.0164，双源最大 ~0.0328），**别拿它画进度条**，会被压成全 0
> - `sources: ['vector' | 'bm25']` + `vector_rank` / `bm25_rank` 才是解释「为什么命中」的关键，比分数本身有用
> - **早期的 `score_threshold`「阈值」交互已废弃**：RRF 分没有可解释的阈值语义，
>   后端不再接收该字段。要做「只看前 N 条」用 `top_k` 即可

### 5.4 模型 & 提示词

#### 5.4 模型 & 提示词

> **拆成三页**（2026-10-21 落地）：不同形态的配置用不同页面 + 不同存储。
> 混在一页的后果是「东西一多就不知道该往哪放」。

| 页面                       | 承接什么                     | 存储               |
| -------------------------- | ---------------------------- | ------------------ |
| `/admin/models`            | 模型列表（多条 + 启用切换）  | `tenant_models`    |
| `/admin/prompts`           | 提示词多版本                 | `prompt_versions`  |
| `/admin/settings`          | 通用配置 KV                  | `tenant_settings`  |

##### 5.4.1 模型选择 `/admin/models`（C4）

AntD Table + 抽屉表单。列：名称（带「启用中」标记）/ 模型 id / Base URL / API Key /
采样 / 操作（启用 · 试连 · 编辑 · 删除）。

- **一条模型 = 一套完整连接配置**（名称 / provider / 模型 id / Base URL / apiKey /
  Temperature / Max Output Tokens / 提示词缓存），互不共享
- 「新建模型」抽屉；编辑时**留空 API Key = 保持原样**（不重填也能改别的字段）
- 每条独立「试连」按钮（真发一次最小请求，不落消息表）
- 第一条模型自动成为启用项；切换在单事务里保证「每租户恰一条启用」
- 顶部横幅常驻显示「当前对话走哪条」，没有启用项时提示走平台默认

> **与原规格的差异**：「备用模型下拉」做成「模型列表 + 启用切换」——
> 多条模型比一个下拉更直观，而且能表达「自建网关 + 官方 API 并存」。
> 「Max Tokens」改成 Max **Output** Tokens（默认 2048，对齐 LLM 输出上限语义）。

##### 5.4.2 提示词配置 `/admin/prompts`（C3）

- 左侧：版本列表（草稿 / 生产中 / 已归档 / 生效中）
- 右侧：编辑器（等宽字体）+ 变更说明
- 顶部：「保存草稿」（仅 draft 可点）+「发布」
- 底部：「回滚到 vN」「以此新建草稿」「删除该版本」
- 支持 `{{tenantName}}` 占位符，发布时自动替换成租户名

> **与原规格的差异**：没做「实时预览」和「变更跳评测页」（评测 D1 未落地，跳过去是死链）；
> **production / archived 不能直接改**（已被真实用户用过，静默改等于线上行为无预告漂移），
> 所以历史版本都带「以此新建草稿」。

### 5.9 租户设置 `/admin/settings`（E2）✅ 通用配置页已落地 2026-10-21

**通用 KV 配置页**：后端返回「配置项元信息 + 当前生效值」，前端按 `category` 分区渲染。
加一个配置项 = 后端 `SETTINGS_REGISTRY` 加一条，前端自动多一行，不用改。

- 每项显示：名称 / 当前值 / 平台默认值 / 「已覆盖」标记
- **清空输入框再保存 = 清除覆盖、回落平台默认**
- 非法值（超范围 / 类型不对 / key 不在注册表里）后端直接 400 拒掉

当前 6 项（`.env` 里**适合租户级**的全部搬进来了）：

| 分组 | 配置项 | 对应 `.env` | 说明 |
| ---- | ------ | ----------- | ---- |
| 知识库 | 检索召回条数 | `CHAT_RETRIEVAL_TOP_K` | 语料少时调到 8~10 |
| 知识库 | 最多记多少轮历史 | `CHAT_MAX_HISTORY_TURNS` | AI 忘事就调大 |
| 知识库 | 检索片段 token 上限 | `CHAT_RETRIEVAL_TOKEN_BUDGET` | 调小 = 只喂最相关的 |
| 成本 | 单轮上下文总预算 | `CHAT_CONTEXT_TOKEN_BUDGET` | **单次请求的成本闸门**，调大更贵更慢 |
| 成本 | 单条消息字数上限 | `CHAT_MAX_INPUT_CHARS` | 超了直接 400 拒 |
| 模型 | 思考模式预算 | `CHAT_THINKING_BUDGET_TOKENS` | 0 = 关 |

> **刻意不搬进来的**：加密密钥、SSRF 开关（安全边界）；
> `CHAT_TEMPERATURE` / `CHAT_MAX_OUTPUT_TOKENS`（已在模型条目里，避免两处各存一份）；
> `CHAT_KEEPALIVE_MS` / `CHAT_BUDGET_SAFETY_RATIO` / `CHAT_SYSTEM_TOKEN_BUDGET`（传输层 / 内部估算参数）。

> 刻意**不放**在这里的：加密密钥、SSRF 开关、上下文总预算、SSE 心跳 ——
> 那是安全边界和平台成本边界，留在服务端 `.env`（`docs/12-c` §C4 有分界表）。
