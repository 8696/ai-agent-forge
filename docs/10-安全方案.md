## 10.1 提示词注入防护

- 用户输入先过注入检测（规则 + 大模型二次确认）
- 高风险输入直接拒绝并转人工
- 系统提示单独占一个 role，不与用户输入混合

**实现细则**：

- 规则表在 `src/lib/security/injection.ts`，每条带严重度：
  - `high`：索取系统提示词 / 越狱模式 / 索取密钥 —— 大模型判不出来时**照样拦**
  - `medium`：只是句式像（「扮演」「你现在是」）—— 大模型判不出来时**放行**
- 大模型二次确认用**租户自己的模型配置**（不额外消耗平台凭据），
  超时 `SECURITY_GUARD_TIMEOUT_MS`（默认 8s）按「判不出来」处理
- 策略开关 `.env` 的 `SECURITY_INJECTION_LLM_MODE`：
  `confirm`（默认，只在规则命中时问模型）/ `always`（每条都问）/ `off`（只用规则）

## 10.2 内容审核

- 输入：暴力 / 色情 / 政治 / 歧视四类规则匹配
- 输出：模型回复先过敏感词库，再过大模型审核
- 审核失败的内容不返回给用户，记录到审核日志

**实现细则**：

- 词库在 `src/lib/security/sensitive-words.ts`（四类，纯数据，改词不用碰逻辑）
- 命中即**拒绝**（403），不做「打个标记继续」—— 审核一旦变成提示就等于没有
- 审计日志只记「分类 + 条数」，**不记违规原文**
- ⚠️ **输出审核受 SSE 固有限制**：回答逐字流给浏览器，字节收不回来。
  能保证的是「原文不落库 + 前端把气泡换成拦截文案」，做不到「一个字节都不发」

## 10.3 敏感数据脱敏

- 身份证 / 银行卡 / 手机号从日志和 trace 中自动脱敏
- 用户上传的文档单独加密存储

**实现细则**：

- 脱敏在 `src/lib/security/mask.ts`，**排在安全链路的第 0 步**：
  后面所有环节（审核 / 检索 / 落库 / 日志 / prompt）拿到的都是脱敏后的文本
- 银行卡要过 Luhn **或**卡号前缀白名单才脱敏，否则 16 位订单号会被当成卡号抹掉
- 用户上传的文档加密存储 —— ⚠️ **本期未做**（文档目前落磁盘明文，见 `AGENTS.md` 已知限制）

## 10.4 鉴权

- 用户：邮箱 + 密码（bcrypt）+ JWT
- API Key：每个租户一个，权限按 scope 分（只读 / 写入 / 管理员）
- 后台 API：JWT + 角色权限

## 10.5 工具调用权限

- 每个工具标注允许的调用方（哪些代理能调）
- 敏感工具（改单、退款）必须审核代理二次确认
