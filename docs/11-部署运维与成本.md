# 11 · 部署运维与成本

> 本项目不部署到云，全部通过 localhost 访问。

## 11.1 一键启动

整个项目只需**两条**命令（在项目根目录）：

```bash
docker compose up -d    # ① 起 MySQL 8.0 / Qdrant 两个容器
yarn dev                # ② 起前后端
```

⚠️ **`yarn dev` 不会自己拉起 docker**（它只是 `concurrently` 并行跑前后端，
外加后端启动前的 `yarn migrate`）—— 先把容器起好，否则后端会连不上库：

1. `docker compose up -d`：在本地启动 `MySQL 8.0` / `Qdrant` 两个容器
2. `yarn dev` 里的 `concurrently` 并行启动 `src/`（后端，监听 3000）和 `web/`（前端，监听 5173）；
   后端启动前会先跑 `yarn migrate`（只跑 pending 的迁移）

> 💡 数据卷用的是 **docker 命名卷**（`mysql_data` / `qdrant_data`），
> 不是 `./data/mysql-data/` 这样的目录 —— 备份见 §11.4。

## 11.2 访问入口

启动成功后，本地访问入口：

| 入口 | 地址 | 用途 |
|------|------|------|
| 聊天挂件 | http://localhost:5173/widget/{tenant-code} | 给前台用户嵌入网页用的对话界面（`{tenant-code}` 是租户的短代码，不是 UUID） |
| 管理后台 | http://localhost:5173/admin | 后台用户（admin / agent）登录后的控制台 |
| 系统级入口 | http://localhost:5173/system | SaaS 平台方建租户（如果有 UI 的话） |
| 后端 API | http://localhost:3000 | 前后端对话的统一接口 |
| 健康检查 | http://localhost:3000/**api**/health | 后端存活检查（路由挂在 `/api` 前缀下） |
| Qdrant Dashboard | http://localhost:6333/dashboard | 向量库的可视化界面 |

## 11.3 环境配置

- 所有配置走 **根目录的 `.env`**（一个文件管所有）
- `.env.example` 提供模板（**键名以 `.env.example` 为准**，下面是最常改的几个）：
    - `PORT`（后端端口，默认 3000；测试实例用 3099）
    - `MYSQL_HOST` / `MYSQL_PORT` / `MYSQL_USER` / `MYSQL_PASSWORD` / `MYSQL_DB`
      —— **不是一个 `MYSQL_URL`**，是拆开的五个
    - `QDRANT_URL` / `QDRANT_COLLECTION`（默认 `documents`）
    - `LLM_PROVIDER`（`minimax` / `zhipu` / `deepseek` / `qwen` / `custom`）
      + **对应 provider 的密钥**（`MINIMAX_API_KEY` / `ZHIPU_API_KEY` /
      `DEEPSEEK_API_KEY` / `QWEN_API_KEY` / `CUSTOM_API_KEY`）
      —— **不是 `ANTHROPIC_API_KEY` / `OPENAI_API_KEY`**，
      那是 AI SDK 内部 provider 的名字，不是本项目认的键
    - `JWT_SECRET`（**生产必须改**，默认值是开发用的）
- 子项目不单独维护 `.env`

## 11.4 数据备份（手动）

虽然不部署到云，但本地数据要定期备份（用脚本，不自动跑）：

```bash
# 备份 MySQL（库名 / 账号跟 .env 的 MYSQL_* 一致）
mysqldump -u root -p agent_platform > ./backups/mysql-$(date +%Y%m%d).sql

# 备份 Qdrant（collection 名跟 .env 的 QDRANT_COLLECTION 一致，默认 documents）
curl -X POST http://localhost:6333/collections/documents/snapshots

# 备份上传的文档（落盘路径是 {DATA_DIR}/uploads/{tenant_id}/…，默认 DATA_DIR=./data）
tar -czf ./backups/uploads-$(date +%Y%m%d).tar.gz ./data/uploads/
```

备份建议保留到外置硬盘或网盘，不要只存在本机。

> ⚠️ **MySQL 跑在 docker 命名卷里**（`mysql_data`），不是 `./data/mysql-data/` 目录 ——
> 备份走 `mysqldump`（上面那条命令）就行，不用去翻目录。

## 11.5 故障排查

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| `yarn dev` 报端口被占 | 上次没正常退出 | `lsof -i:3000` / `5173`，找到 PID `kill` |
| MySQL 连不上 | docker 没起来 | `docker compose ps`，看 MySQL 状态 |
| 文档列表 500 + 日志 `Unknown column 'xxx' in 'field list'` | 迁移没跑 | `yarn migrate`（007 建表 / 008 补字段） |
| 上传报「Embedding 维度不符」 | 换了 embedding 模型但没重建 collection | `curl -X DELETE http://<QDRANT_URL>/collections/documents`，然后**把知识库里的文档全部重新索引**（旧向量已随 collection 删除） |
| 上传报「Embedding API 返回 4xx」 | provider 没 key / 欠费 / 该 provider 不支持 embedding | 检查 `.env` 里对应 `*_API_KEY` 和 `*_EMBEDDING_MODEL`；DeepSeek 不提供 Embedding |
| 检索只有关键词命中、没有语义命中 | BM25 进程内索引正在重建 | 看启动日志「BM25 索引已从 Qdrant 重建」；期间只有向量一路可用，重建完自动恢复 |
| 文档列表「关键词索引块数」明显小于「已索引块数」 | 同上，重建中；或 BM25 写入失败 | 看日志「BM25 索引写入失败」，重启会自动重建 |
| `data/tmp/` 目录越来越大 | 异常路径的临时文件没清干净 | 停服务后直接删该目录内容；正常路径已自动清理，只可能是崩溃/强杀留下的 |
| 向量检索返回空 | Qdrant 没数据 | 上传一份文档试；确认 `.env` 的 `QDRANT_URL` 指向正确实例 |
| Agent 回复慢 | 大模型 API 慢 | 看 `.env` 的 `LLM_PROVIDER` 和**对应 provider 的密钥**是否有效；切到更轻的模型 |
| 端口冲突 | 别的项目用了 3000 / 5173 | 改 `vite.config.ts` 的 port 和后端 `PORT`，重启 |

## 11.6 不做的事

本项目**不在此文档范围内**：

- ❌ 部署到云（Vercel / Railway / 阿里云 / AWS）
- ❌ HTTPS / 域名 / Let's Encrypt
- ❌ CI/CD 自动化（GitHub Actions 自动构建）
- ❌ 云端监控告警（Uptime Kuma / Grafana Cloud）
- ❌ 异地备份 / 冷存储归档
- ❌ 容器编排（Kubernetes）

如果将来要部署，再单独写一份「部署指南」文档，不在本文档展开。

## 11.7 成本估算（仅 API 调用 · 本地运行无云费用）

### 假设

- 1000 DAU（日活跃用户）
- 每用户每天 10 轮对话
- 每轮对话平均 1500 input tokens + 500 output tokens
- Embedding：每条文档 800 字 + 每条问题 50 字
- 向量库：100 万文档块

### LLM 成本

- 主对话：1000 × 10 × (1500 × $3/M + 500 × $15/M) / 1e6 = $120/天
- 检索查询改写：1000 × 10 × 200 × $3/M / 1e6 = $6/天
- 评测：200 条 × 4 次/天 × 2000 tokens × $3/M / 1e6 = $5/天
- **LLM 月费**：~$3900

### Embedding 成本

- 文档 embedding：100 万块 × 800 字 × $0.02/M = $16 一次性
- 查询 embedding：1000 × 10 × 50 × $0.02/M = $0.01/天 ≈ $0.3/月
- **Embedding 月费**：~$1

### 基础设施成本

本地运行，**云基础设施费用为 0**：

- MySQL：Docker 容器跑在本地机器，$0
- Qdrant：Docker 容器跑在本地机器，$0
- 对象存储：用本地磁盘 `./data/uploads/`，$0
- 服务器 / 托管：用自己的机器，$0

### 1000 DAU 总成本（仅 API）

```
LLM API：       $3900
Embedding API：  $1
基础设施：      $0
────────────────
合计：          $3901/月
每用户：        $3.90/月
```

### 10000 DAU 推算

```
LLM API：       $39000
Embedding API： $10
```

**注意**：10000 DAU 折合 ~300 req/s 峰值，普通开发机撑不住（双发单卡可扛 ~30 req/s）。本地开发 / 演示场景，建议把规模控制在 **1000 DAU 以内**；真正上量必须部署到云，那是另一份文档。

### 优化方向（本地开发也适用）

- 用 prompt caching 节省 30-50% 的 system + retrieval token
- 用更便宜的模型做查询改写 / 内容审核
- 加缓存层（相同问题直接返回缓存）
- 加批处理（多条 embedding 一次调用）
